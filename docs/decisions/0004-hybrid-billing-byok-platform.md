# ADR-0004：平台模型默认 + BYOK 可选 + 订阅与超额资源计费

- 决策状态：已确定（2026-11-12）
- 生效范围：SuperNova 多租户控制平面、OpenAI 兼容网关、后续 AstrBot Worker / 知识库 / 渠道
- 决策人：产品负责人
- 关联：ADR-0002 OpenAI 兼容网关；Phase 4 usage_records

## 业务决策

1. **新租户默认选择平台模型（platform）**：SuperNova 统一提供模型调用能力，负责下游供应商费用及本平台对用户的定价。
2. **允许用户为单个人格选择 BYOK（自带模型 API Key）**。BYOK 的模型调用由用户自己的供应商直接计费，SuperNova 对这些模型 Token 收取 **0 模型费用**。
3. **主要收入 = SaaS 订阅费 + 明示的超额资源费**。同一平台能力不得在不同条目重复收费。
4. 平台模型可以包含套餐赠送的模型使用额度；超额部分依照可追溯的价格版本结算。BYOK 不参与平台模型额度消耗。
5. 超额自动扣费默认关闭。用户须主动开启、选择支付/预付方式和消费上限后，才能产生收费超额；否则达到额度就阻止新增应收费操作（429/402，具体接口规范另定）。
6. 任何配置或迁移 **不得影响已经存在的用户 Key、人格、模型供应商和使用数据**。

## 区分三类计量

| 类型 | 举例 | 平台模型 | BYOK |
| --- | --- | --- | --- |
| 模型使用 | 输入/输出 Token、按模型及版本归属 | 计量与结算 | 仅展示，不收 SuperNova 模型费 |
| 平台资源 | API 请求、知识库存储/解析、向量索引、机器人在线实例/计算资源 | 依套餐计量/超额 | 依套餐计量/超额 |
| 金额 | 订阅、超额资源、平台模型超额、退款及补偿 | 按规则结算 | 不包含 BYOK 模型费用 |

同一个资源代码只有一条计价规则。对于套餐已覆盖的资源量，超额金额为零，不得再依其他名称重复收取。

## 默认平台模型的生命周期

- 后台「模型来源」允许用户在 **平台模型（默认）** 与 **自带 API Key（BYOK）** 中切换；**一个人格同一时刻只能选择一种模型来源**。
- 平台模型：只选平台提供的 model code，用户不能读取或覆盖平台供应商密钥。平台模型密钥留在 SuperNova 的服务端秘密管理系统/受控运行时。
- BYOK：选择当前租户的 model_providers，API Key 延续现有 Fernet 加密存储。
- 网关认证维持 **一个用户级 API Key 可通过 model=人格 slug 调用多个独立人格**。计费来源取人格配置，不取客户端伪造的 billing_mode 字段。
- 不允许请求时隐式回退来源，尤其是平台模型余额不足时不可悄悄改用 BYOK，反之亦然。

## 兼容迁移规则

- 现有 personas.provider_id、personas.model_name、ModelProvider 及加密密钥均不动。
- 为 persona 增加 model_source / platform_model_id：**现有所有 persona 先标记 BYOK**（包括尚未绑定供应商的草稿），保持现有行为；只有新建人格在新版 UI 默认平台模型。
- tenant_billing_policies 未初始化的旧租户按迁移前功能继续使用 BYOK；首次明确选择套餐后才启用平台模型计费。
- 无明示的已生效套餐、有效平台模型凭据、额度或预授权时，**不得调用平台付费模型**。
- 老 usage_records 保持历史事实，仅供观察；**不得根据历史未评级记录自动回扣费用**。
- 不强制迁移、删除、重写或覆盖已有密钥；取消服务时仍保留历史账务快照（按适用数据保留政策）。

## 计价与结算原则

- 不在前端、网关请求参数或模型供应商响应中相信用户自己提供的价格。
- 按模型 + 版本 + 输入/输出 Token 分别计价；平台成本价格与面向客户的销售价格分离。
- 费用统一以 **币种最小单位**（如 CNY 分）及 Decimal 高精度中间值计算；最终结算在发票/单笔扣款边界按明确规则舍入，绝不使用 float 计费。
- 资源超额费按套餐版本的 included_units、单位、计价阶梯与允许超额策略计算。
- 先检查订阅、额度与预算，再预留额度/余额；调用完成后凭真实供应商 usage 清算。流式异常、中断、供应商未返回 usage 要有独立处理流程，不能默认按 max_tokens 全额扣费。
- 供应商未返回 usage 的记录进入 **unmetered 待对账**；在无可靠用量证明时不得自动收取模型费。
- 以唯一事件 ID + 持久幂等约束保证同一个业务用量事件只能结算一次。余额更新与记账必须处于同一个数据库事务，采用行锁或等价并发控制。
- 修改价格后生成新 price_version，已发生的资源用量继续按当时绑定版本结算，不受历史定价修改影响。
- 钱包充值、订阅支付以支付渠道的服务端回调及事件幂等核实为准，不能以浏览器跳转/支付成功页面为依据。
- 不对外宣传「不限量」而不声明公平使用规则、并发、速率和超额限制。

## 安全与财务边界

- 新表均绑定 tenant_id（公共平台目录和平台账务科目除外）；读取和修改需 tenant 隔离。
- 租户不能创建平台供给的模型价格、平台供应商 Key、收款记录或账本分录；这些是管理端后台专属操作。
- 管理员调整余额必须生成可审计的调整交易，不允许直接 UPDATE wallet.balance。
- 所有涉及金钱的 API 使用显式 idempotency key、操作人、request ID、时间戳、价格版本和完整审计。
- **本 ADR 与数据库准备迁移不代表已启用扣费**。在幂等/并发/失败/回调/授权等验收前，收费开关须保持关闭。

## 明确不做

- 现阶段不在 BYOK Token 上收平台模型差价。
- 不允许零成本模型「自动兜底」为高成本平台模型。
- 不把原生 Token 计量当作账单金额。
- 不在没有定价版本/受控预算的情况下对已有用户追缴历史用量。
