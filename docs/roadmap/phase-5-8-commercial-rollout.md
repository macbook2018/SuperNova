# SuperNova 后续开发路线（混合模型 / 订阅 + 超额资源）

产品决策：默认平台模型，允许 BYOK；主要营收 SaaS 订阅和超额资源费。

## 现状与依赖

- Phase 0–3：基础、中文控制台、租户身份、人格与供应商管理已开发。
- Phase 4：OpenAI 兼容网关和 Token 用量已开发，已由用户完成 DeepSeek 实际调用和后台用量验证。当前 PR #5 / #6 尚未合并。
- 下一开发从包含 PR #6 修复的分支衍生，**不直接在 main 上跳过依赖开发**。
- 不将目前 usage_records 直接用来收钱；它只证明使用量记录能力，不是完整可追溯的财务系统。

## Phase 5A — 混合计费基础（当前）

交付：
1. ADR-0004：平台模型默认/BYOK 可选与双轨收费不重复。
2. 计费域、资源 SKU、额度、价格版本和账本设计。
3. 非破坏性 Alembic 0005 迁移、ORM、Decimal 纯函数估价、基本迁移/单元测试。
4. Billing 状态均不自动生效；支付、实际扣费、平台代理保持关闭。

验收：
- 原用户、原人格、原 BYOK Key、原模型调用完全兼容。
- 已有 Persona 迁移后 model_source=byok，新租户 UI 后续默认 platform。
- 单价/额度支持版本快照和审计。
- BYOK 纯模型 Token 的平台模型收费恒为 0。
- 账本算式可以做平衡校验，创建事件、订阅等 schema 通过迁移/测试。

## Phase 5B — 平台模型目录与来源切换（已完成）

**完成日期：2026-11-12；验收：60 项 API 测试通过，数据库迁移、Docker 冒烟测试及控制台生产构建全部通过。**

交付：
- 平台模型池和模型价格版本；平台管理员通过邮箱白名单管理目录，凭据只从服务端配置的 credential_ref 解析。
- 新建人格在控制台默认选择平台模型；支持切换 BYOK；已有 Persona 保持 BYOK。
- 网关按 Persona.model_source 双路由，SSE/非流式调用共用路由和用量记录。
- 新租户创建 TenantBillingPolicy；套餐、订阅分配、权益查询和调用前额度检查。
- BYOK 的平台模型 Token 费用为 0，但仍受订阅中的 API 请求额度约束。
- 本阶段超额一律拒绝，不执行钱包扣款、预留或正式结算。

验收：
- 平台 Key 不返回租户 API、控制台或用量记录。
- BYOK 与平台模型路由隔离，禁止自动回退。
- 平台模型必须有当前币种的有效价格版本和服务端凭据。
- 新租户没有有效订阅时不能调用平台模型或 BYOK；没有计费策略的历史租户继续兼容原 BYOK。
- 套餐权益按订阅周期计算，超额请求返回明确 quota_exceeded。
- 并发额度预留/防透支属于 Phase 5C，不在本阶段宣称已完成。

## Phase 5C — 额度、计价与账本（先影子计费，已实现）

**完成日期：2026-11-12；CI：68 项 API 测试通过，PostgreSQL 并发集成测试、迁移、Docker smoke 和 Console 构建全部通过。**

交付：
- PostgreSQL 租户级行锁与 reservation items，实现 API 请求、平台模型请求、输入/输出 Token 的并发额度预留。
- Chat Completions 支持 Idempotency-Key；同 Key 同请求的非流式成功响应重放，冲突 Payload 返回 409；SSE 重放返回 409，不重复调用上游。
- 可信 usage 才能结算；输入/输出按调用时价格版本分别 Decimal 计价，BYOK Token 费用为 0。
- unknown usage 保留 Token 预留；管理员可基于供应商账单人工补录结算，或审计后释放。
- 成对平衡的 shadow ledger postings、不可变价格版本引用、人工处理审计和对账运行记录。
- 租户控制台显示 reserved/remaining、影子估算金额、平台/BYOK Token 和最近影子账本。
- 币种最小单位精度覆盖 0/2/3/4 位小数。

验收：
- 幂等 Key 重放、Key 与 Payload 冲突、预留阻止额度透支有自动化测试。
- PostgreSQL 并发集成测试验证两个并发请求争抢最后一个 API request 额度时只有一个成功预留。
- 缺失/不可信 usage 不生成 Token 评级；未知预留等待人工核对。
- 影子账本每笔交易至少两条 posting，净额为 0；对账核对评级总额与账本正向分录。
- JPY/KRW、CNY/USD、KWD、CLF 等币种精度有测试。
- 本阶段不扣真实余额、不启用超额收费、不接支付。

运维边界：
- `POST /admin/billing/reconciliation/run` 可执行日报；由部署环境 Cron/调度器每日调用。
- 过期 held reservation 先标记为 unknown；管理员核实后 settle 或 release。
- 完整实施说明见 `docs/phase-5c-implementation-report.md`。


## Phase 5D — 商业化支付及真实收费（最后实施，暂缓）

交付：
- 支付/订阅适配器；签名验证、回调 inbox 幂等、退款流程。
- 手动开通/取消套餐、周期续费、停用后的明确行为。
- 充值/预付余额与消费上限、支付失败处理、发票/税费规则。
- 管理端价格管理/收入和财务对账看板。

验收：
- 完整沙盒支付成功、失败、超时、退款、乱序/重复回调测试。
- 无显式授权不得自动超额消费。
- 独立审核平台资金操作、生产密钥和财务日志。

## Phase 6 — 完整知识库与 RAG 检索（当前优先阶段）

交付：文档/网址导入、解析切片、Embedding、pgvector、检索引用、增量更新、删除与租户隔离；嵌入、存储、解析资源纳入计量。避免文档处理消耗的额度与模型 Token 双重收费。

## Phase 7 — AstrBot 多租户运行环境

交付：机器人 Worker 管理、独立 Persona/知识库/插件、渠道状态、实例生命周期、隔离与恢复；按实例小时、并发等收取明示超额资源费。

## Phase 8 — 渠道、运营与规模化

交付：微信已跑通的接入链路产品化、其他渠道、权限/协作、企业租户、运营报表、风控、计费对账、商用部署与监控。

## 下一阶段开发顺序

用户已明确调整商业化顺序：**先完成 Phase 6 完整知识库与 RAG 检索 → Phase 7 AstrBot 多租户运行环境 → Phase 8 渠道、运营与规模化 → 最后实施 Phase 5D 商业化支付及真实收费**。Phase 5D 在知识库、机器人运行环境和渠道产品化验收之前保持冻结；Phase 5C 影子计量继续运行但不扣款。

只要真实资金相关验收未完成，所有计费保持 dry-run/shadow，不对现有用户自动产生费用。

## 阶段执行约束

- Phase 6 从 `feat/phase-5c-idempotent-metering-settlement` 分支继续，保留 Phase 5C 的额度预留、影子计量与对账能力。
- 不要求先接支付，也不以真实扣费作为知识库上线前置条件。
- 知识库文档处理资源与模型 Token 分开计量，避免重复收费；Phase 5D 最后再决定正式 SKU、套餐额度和超额价格。

## 价格配置

产品建议：免费/基础/专业/企业套餐可用于市场试验，但不应写死到代码与迁移中，也不应向用户展示未发布价格。支持用户选择按月/按年，发布后通过版本号固定历史价格。实际币种、税费、支付供应商与模型价格由业务测试确认。
