# 多租户数据隔离与安全边界

## 一、身份模型

用户级接口密钥是外部 API 的身份凭据。每个密钥必须绑定以下信息：

- user_id：用户编号
- tenant_id：租户编号
- key_prefix：密钥前缀，用于控制台展示和检索
- key_hash：不可逆的密钥验证值
- status、created_at、last_used_at、expires_at、revoked_at：状态和时间信息

接口密钥明文只在创建成功时展示一次。服务端不得记录密钥明文。

## 二、请求上下文

认证中间件验证密钥后，生成不可由客户端覆盖的请求上下文（RequestContext），至少包含：

- request_id：请求编号
- user_id：用户编号
- tenant_id：租户编号
- api_key_id：接口密钥编号
- scopes：授权范围

业务服务只能从已验证的请求上下文获取用户和租户身份。不得信任请求体、查询参数或自定义请求头中的 tenant_id / user_id。

## 三、数据库隔离

所有租户业务表必须包含 tenant_id。用户私有资源还应记录 owner_user_id。每次读取、更新和删除都必须同时约束资源编号和授权范围，不能仅凭全局 UUID 查询后直接返回数据。

pgvector 向量检索必须在相似度查询前或同一条 SQL 查询中强制加入 tenant_id 过滤。数据库行级安全策略（Row Level Security）可以作为纵深防御，但不能替代应用层授权。

## 四、文件、缓存与运行资源隔离

- S3 对象键使用 tenant/{tenant_id}/... 前缀；下载前重新验证资源归属。
- Redis 键使用 tenant:{tenant_id}:... 命名空间；不得跨租户复用会话缓存。
- 运行实例配置、临时文件和日志必须带有租户边界；不同租户的运行实例不得共享可写工作目录。
- 模型凭据和渠道凭据按最小权限注入运行实例，不得写入镜像或代码仓库。

## 五、运行实例隔离

首期按租户隔离 AstrBot 容器。运行实例管理器负责创建、启动、停止、健康检查和回收。容器应配置 CPU、内存、网络和文件系统限制。控制平面仅通过内部服务身份访问运行实例。

## 六、必须覆盖的安全测试

1. 用户 A 使用自己的密钥请求用户 B 的人格，必须拒绝。
2. 用户 A 猜测用户 B 的知识库、文档、会话或文件 UUID，必须拒绝。
3. 用户 A 不能通过传入其他 tenant_id 改变数据访问范围。
4. 已撤销或过期的密钥必须立即失效。
5. 用户 A 的运行实例不能读取用户 B 的文件、凭据或会话。
6. 向量检索、缓存命中和对象下载均必须验证租户归属。

## 七、日志与隐私

日志记录请求编号、租户编号、用户编号、密钥编号、路由、耗时、Token 数量和错误代码。不得记录接口密钥、模型供应商密钥、微信登录凭据或完整敏感对话内容。
