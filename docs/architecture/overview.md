# 系统架构总览

## 一、建设目标

SuperNova 采用控制平面与运行平面分离的架构。控制平面负责管理平台用户和业务资源；AstrBot 运行实例负责执行智能体任务；统一模型网关为外部业务系统提供兼容 OpenAI 标准的调用接口。

## 二、逻辑组件

~~~mermaid

    Client[业务系统 / OpenAI SDK] --> Gateway[统一接口网关]
    Console[SuperNova 中文控制台] --> Control[平台管理服务]
    Gateway --> Auth[接口密钥身份验证]
    Auth --> Persona[人格与权限校验]
    Persona --> Router[模型与智能体路由]
    Router --> Worker[租户隔离的 AstrBot 运行实例]
    Worker --> Provider[模型供应商]
    Worker --> KB[知识库检索服务]
    Control --> DB[(PostgreSQL + pgvector)]
    Gateway --> DB
    Control --> Redis[(Redis)]
    Control --> Storage[(S3 兼容对象存储)]
    Control --> Manager[运行实例管理器]
    Manager --> Worker
~~~

## 三、控制平面职责

- 用户、租户、成员和权限管理。
- 用户级接口密钥的创建、轮换、撤销和审计。
- AI 人格配置、模型供应商及模型凭据管理。
- 知识库、文档、索引和检索配置。
- 渠道、会话、用量、套餐和计费记录。
- AstrBot 运行实例的创建、配置下发、健康检查、重启和回收。

## 四、运行平面职责

- 使用 AstrBot 执行智能体对话。
- 加载人格设定、插件、知识库检索适配器和渠道适配器。
- 通过内部协议调用模型网关或受控的模型供应商。
- 上报会话事件、Token 用量、运行状态和错误信息。

## 五、关键请求流程

1. 客户端向统一 Base URL 发送请求，并携带用户级接口密钥。
2. 统一接口网关验证密钥，解析用户编号、租户编号、密钥状态和权限。
3. 网关根据请求中的 model 找到该用户有权访问的人格；客户端不能自行指定任意运行实例。
4. 网关将规范化请求转发至该人格所属的 AstrBot 运行实例。
5. 运行实例执行智能体逻辑、知识检索和模型调用。
6. 网关将结果转换为兼容 OpenAI 标准的响应；流式请求通过 SSE 返回。
7. 请求用量、耗时、请求编号和错误状态写入审计及计量记录。

## 六、架构边界

- 控制平面不直接承载长时间运行的智能体进程。
- 运行实例不能访问其他租户的数据库记录或对象存储目录。
- 外部 API 不暴露运行实例的内部网络地址和内部凭据。
- 优先通过适配器兼容 AstrBot 上游升级，避免长期维护侵入式分支。
- 已完成的微信收发验证不重复建设；进入渠道阶段时将其作为回归验收基线。

## 七、界面语言

SuperNova 自有控制台、管理后台、接口文档和面向用户的提示信息默认使用简体中文。API 路径、JSON 字段、数据库字段和第三方协议名称保留标准英文。
