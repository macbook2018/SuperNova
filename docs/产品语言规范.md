# SuperNova 产品语言与界面规范

## 一、默认语言

- 默认语言为简体中文，语言代码为 zh-CN。
- 新建页面、弹窗、表单、菜单、按钮、通知、邮件模板、错误提示、账单和帮助文档，必须默认使用简体中文。
- 不得在同一个页面中无规则地混用中文和英文。
- 用户可见的英文术语应优先使用中文解释；确实需要保留的专业名称，可在首次出现时使用“中文名称（英文名称）”。
- 将来增加英文版本时，使用独立语言包管理，不得用英文覆盖中文默认界面。

## 二、必须使用中文的范围

1. 用户注册、登录、退出登录、密码找回和账号安全。
2. 控制台导航、页面标题、菜单、按钮、表单字段和字段说明。
3. 人格创建、人格提示词、模型配置和模型供应商设置。
4. 知识库创建、文件上传、链接导入、切片、索引和检索设置。
5. 微信渠道、机器人连接状态、会话管理和消息记录。
6. 接口密钥、接口调用示例、调用记录和错误说明。
7. Token 用量、套餐、余额、账单、充值和消费明细。
8. 用户通知、系统公告、帮助中心和客服指引。
9. 平台运营后台中的用户、租户、套餐、订单、财务和系统设置。

## 三、保留英文的技术标识

以下内容必须保留标准英文，不得为了界面中文化而修改协议：

- API 路径，例如 /v1/chat/completions。
- JSON 字段，例如 model、messages、stream。
- HTTP 请求头，例如 Authorization、Content-Type。
- 数据库字段、代码变量、函数名、环境变量和命令行参数。
- OpenAI、AstrBot、PostgreSQL、Redis、SSE、JWT、Token 等标准技术名称。

在用户界面中可以将这些术语显示为中文说明，例如“接口密钥（API Key）”“基础地址（Base URL）”“模型人格（model）”“流式输出（SSE）”。

## 四、错误提示规范

- 错误提示应说明发生了什么，以及用户下一步可以做什么。
- 不得直接把 Python 异常、数据库报错、堆栈或第三方英文错误原文展示给普通用户。
- 每条错误信息应包含稳定的错误代码和请求编号，便于客服和技术人员定位。
- 不得在错误提示中泄露接口密钥、模型供应商密钥、内部地址或其他租户的数据。

## 五、第三方组件边界

SuperNova 自有产品界面必须使用简体中文。第三方组件的语言能力由对应项目决定：当前开发环境使用的 Silo 版本已内置简体中文，进入对象存储管理控制台后，可点击右上角语言菜单并选择“简体中文”；PostgreSQL、Redis、AstrBot 等其他第三方组件仍按各自提供的语言能力使用。SuperNova 应尽量通过中文后台封装常用操作，避免要求普通用户直接进入第三方管理控制台。

## 六、验收要求

每个前端阶段至少检查：

- 页面无遗漏的英文菜单、按钮、表单标签和提示语。
- 登录、权限、网络、上传、模型调用和计费异常均有中文提示。
- 空状态、加载状态、成功状态和确认弹窗均为中文。
- 关键页面在刷新、重新登录和不同浏览器语言设置下仍默认显示简体中文。
